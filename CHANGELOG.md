# Changelog

## [Unreleased]

### Breaking: the agent servers listen on 127.0.0.1, and need a chat secret to listen wider

`wunderland start`, `wunderland serve` and `createWunderlandServer()` listened on `0.0.0.0`. `POST /chat` answers without a secret unless one is set, `createWunderlandServer()` never checked one, and its `POST /api/tools/<name>` runs tools in autonomous mode with no key unless `WUNDERLAND_TOOL_API_KEY` is set, so any machine that could reach port 3777 could use the agent, its model key and its tools.

- Both servers listen on `127.0.0.1` unless a host is named: `--host <address>` for `wunderland start` and `wunderland serve`, `host` for `createWunderlandServer()`. A bracketed IPv6 address (`[::1]`) works too, and `--host` with no address is an error.
- A host other machines can reach needs a chat secret: `chat.secret` in `agent.config.json`, `WUNDERLAND_CHAT_SECRET`, or `createWunderlandServer({ chatSecret })`. Without one the server refuses to start.
- `createWunderlandServer()` requires the chat secret on `POST /chat` (the `x-wunderland-chat-secret` header, or `?chat_secret=`), as `wunderland start` does.
- `createWunderlandServer()`'s tool API answers other machines only with `WUNDERLAND_TOOL_API_KEY` in `x-api-key`; without the key it serves this machine only.
- Startup prints the address it listens on.
- `wunderland serve` passes `--host` to its child and records it with the daemon; serve's health poll, the restart watchdog, `ps`, `monitor` and the dashboard check `/health` there.
- `wunderland deploy` writes a Dockerfile that starts the server with `--host 0.0.0.0`, and a `WUNDERLAND_CHAT_SECRET=` line in `.env.example` and a README section on it: the container refuses to start until the secret is set.

Migration: to reach a server from another machine, a container's published port or a proxy on another host, pass `--host 0.0.0.0` (or `host: '0.0.0.0'`) and set a chat secret; clients send it in the `x-wunderland-chat-secret` header. Code that calls the library's tool API from another machine sets `WUNDERLAND_TOOL_API_KEY` and sends it in `x-api-key`. Dockerfiles generated by an earlier `wunderland deploy` need `"--host","0.0.0.0"` in their `CMD` and `WUNDERLAND_CHAT_SECRET` in their environment. Local use needs no change.

## [0.72.0] - 2026-05-09

### BREAKING CHANGES — public surface migration

The `package.json` `exports` field collapsed from 14 declared subpaths to 3. The `wunderland/advanced/*` re-export shelf was removed. Consumers should import named exports from the root `wunderland` package instead.

#### Migration table

| Old import | New import |
|---|---|
| `from 'wunderland/advanced'` | `from 'wunderland'` |
| `from 'wunderland/advanced/core'` | `from 'wunderland'` |
| `from 'wunderland/advanced/security'` | `from 'wunderland'` |
| `from 'wunderland/advanced/social'` | `from 'wunderland'` |
| `from 'wunderland/advanced/<anything>'` | `from 'wunderland'` |
| `from 'wunderland/workflows'` | `from 'wunderland'` |
| `from 'wunderland/api'` | `from 'wunderland/api'` (path preserved, dist target updated) |
| `from 'wunderland/discovery'` | `from 'wunderland/discovery'` (path preserved, dist target updated) |
| `from 'wunderland/tools'` | `from 'wunderland'` (subpath removed; named exports moved to root) |
| `from 'wunderland/config'` | `from 'wunderland'` (subpath removed) |
| `from 'wunderland/security'` | `from 'wunderland'` (subpath removed) |
| `from 'wunderland/runtime'` | `from 'wunderland'` (subpath removed) |
| `from 'wunderland/storage'` | `from 'wunderland'` (subpath removed) |
| `from 'wunderland/voice'` | `from 'wunderland'` (subpath removed) |
| `from 'wunderland/browser'` | `from 'wunderland'` (subpath removed) |
| `from 'wunderland/guardrails'` | `from 'wunderland'` (subpath removed) |
| `from 'wunderland/presets'` | `from 'wunderland'` (subpath removed) |

#### Internal layout

`packages/wunderland/src/` regrouped from 26 top-level directories into 9 themed groups: `agents/`, `runtime/`, `memory/`, `channels/`, `autonomy/`, `security/`, `platform/`, `cli/`, `types/`. Internal API is unaffected for consumers using the root `wunderland` package import.

### Other changes

- README hero rewritten around the autonomous-agents-anywhere identity
- "Built on OpenClaw" framing corrected to "Built on AgentOS"; OpenClaw stays as competitive parity tracking
- `Wunderland on Sol` content moved to [`apps/wunderland-sol/`](https://github.com/manicinc/wunderland-sol)
- Three empty stub packages (`wilds-family-{arcade,platformer,survival}`) removed from monorepo
